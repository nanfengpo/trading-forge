## 0. 核心思想的数学化

系统的存在理由是让「**盈亏比 × 入场成功概率 > 1**」长期成立。把它放进期望值框架（以 1R = 单笔止损金额为单位）：

- 每笔期望值：`E = p × RR − (1 − p)`（单位 R）
- 盈亏平衡概率：`p* = 1 / (1 + RR)`
- **门槛 `p × RR > 1` 等价于 `p > 1/RR`，严格高于盈亏平衡**。在门槛边界上期望值恰好等于 `p`（恒为正）——不等式天然内嵌安全边际，而不是贴着盈亏平衡飞。

| RR | 盈亏平衡 p* | 本系统门槛 p | 门槛处期望值 |
|----|------------|-------------|-------------|
| 1.5 | 40% | 66.7% | +0.67R |
| 2.0 | 33.3% | 50% | +0.50R |
| 2.5 | 28.6% | 40% | +0.40R |
| 3.0 | 25% | 33.3% | +0.33R |

### 0.1 两类交易，两个验收判据（对原始公式的一个必要修正）

字面形式的 `RR × p > 1` 只适用于**方向性交易**（先设计止损再找止盈，RR ≥ 1.5）。它会误杀用户自己已被 8.4 年真实期权链回测验证的 PutWheel：QQQ 车轮单笔胜率 96.6%、平均盈利 +0.44%、平均亏损 −5.78%——盈亏比只有 0.08，`p × RR = 0.08`，但期望值为正（+0.23%/笔）且风险调整收益优于持有（Sharpe 1.35 vs 0.79）。所以系统统一到期望值判据，按交易类型取不同的强形式：

| 交易类型 | 验收判据 | 含义 |
|---------|---------|------|
| **方向性**（趋势/回调/事件，PB-2/3/4/6） | `p × RR > 1` | 用户原始公式，含安全边际 |
| **收租型**（卖权利金，PB-1/5） | `EPR = p×W / ((1−p)×L) ≥ 1.5` **且** 尾部约束 | 期望盈利 ≥ 1.5 × 期望亏损 |

收租型的**尾部约束**（缺一不可）：`L_tail × 仓位 ≤ 1.2 × 该笔风险预算`，其中 `L_tail` 取历史最差单笔与「−35% 跳空 + IV×3」情景推算两者中**更差者**（QQQ 车轮最差单笔 −13.0%，一笔大亏吃掉 13 笔权利金——高胜率的钱是这么亏回去的；新标的没有历史最差，只能用压力情景值）。

收租型还须过**稳健性检验**（三档，v1.1）：取 `p′ = 回测胜率 − 2pp` 重算 EPR′：

| EPR′（p − 2pp 后） | 判定 |
|-------------------|------|
| ≥ 1.5 | 通过，可用 playbook 预设档位全额 |
| 1.3 – 1.5 | **半仓档**：该 playbook 全部仓位预设与 §5.5 闸门按 50% 执行 |
| < 1.3 | 该参数组合禁用 |

EPR 对 p 极端敏感——QQQ 车轮的盈亏平衡胜率高达 95.2%，实测 96.6% 只有 1.4pp 余量，这个余量必须显式检验而不是假设它存在。（v1.0 的单一门槛「−2pp 后仍 ≥ 1.5」会连 QQQ 车轮本身都整体禁掉——其 −2pp 后 EPR ≈ 1.33——与 §7 PB-1「临界附近降仓执行」的条文矛盾；三档化把「临界即半仓」定为明文规则。）

两个判据是同一件事的两面：期望值为正且留有余量。三大纪律不变：

1. **RR 是设计出来的，p 是估计出来的。** 止损/止盈位置决定 RR，可以精确控制；p 只能打分估计且人性倾向高估。对 RR 从严设计、对 p 强制折减（§4）。
2. **不等式成立 ≠ 每笔都赚。** RR=2.5、p=45% 的系统连亏 5 笔的概率约 5%，100 笔内几乎必然出现。单笔风险必须小到连亏 8 笔不伤本金（§5）。
3. **长期成立靠校准闭环。** 不记录预测就无法知道 p 是否高估。日志 + Brier 分数是系统的护城河（§9）。

## 1. 输入参数（用户手动填写）

```yaml
trade_request:
  # —— 标的与方向 ——
  symbol: NVDA                # 标的（股票 / ETF / 期权底层）
  instrument: auto            # stock | option | auto（auto = 系统按 IV 与目标建议工具）
  direction: long             # long | short | neutral（可留空由系统判断）
  horizon: swing              # day(日内) | swing(2–8周) | position(2–6月) | campaign(6月+)

  # —— 目标与风险约束 ——
  objective:
    expected_return: 15%      # 本笔目标收益（占用资金口径）
    max_loss_per_trade: 0.75% # 单笔最大亏损（占账户净值 NAV，或直接给美元数）
    max_drawdown: 10%         # 组合层面可容忍最大回撤（约束总敞口，§5.3）
    sharpe_target: 1.5        # 组合目标夏普（月度验收线，§9）
    vol_tolerance: 20%        # 可承受的组合年化波动率（§5.4）

  # —— 主观判断 ——
  view: |
    （一段话：为什么想做这笔交易——催化剂、逻辑、时间窗口、担心什么）
  conviction: 3               # 信念强度 1–5（只微调仓位 ±25%，不能突破风险上限）
  constraints: []             # 如：不过财报 / 只用现金账户 / 不做裸卖购

account_context:              # 每次会话开头更新一次
  nav: $XXX,XXX
  open_positions: [...]       # 现有持仓（标的、方向、市值、初始止损）
  margin_used: ...            # 保证金利用率（§5.5 闸门要用）
```

### 各参数的含义与作用

| 参数 | 含义 | 驱动什么输出 |
|------|------|-------------|
| `symbol / instrument / direction` | 交易什么、什么工具、什么方向 | 战术路由（§7）、工具选择（IV rank 高 → 期权结构替代正股） |
| `horizon` | 持有周期 | 止损宽度（ATR 周期）、时间止损、辩论轮数（§8） |
| `expected_return` | 本笔目标收益 | 止盈距离与分批方案；与技术空间矛盾会被打回 |
| `max_loss_per_trade` | 单笔风险预算（定义 1R） | **仓位公式分子**（§5.1），系统最硬的约束 |
| `max_drawdown` | 组合回撤容忍 | 总未平仓风险 ≤ `max_drawdown / 2`（§5.3） |
| `sharpe_target` + `vol_tolerance` | 收益/波动预算 | 名义仓位波动约束（§5.4）；是否用期权结构降波动 |
| `view` | 主观论点 | 五层评估逐层对照（§3）；拆成可证伪失效条件（§6.4）；入库打分（§9） |
| `conviction` | 信念强度 | M_conviction ∈ [0.75, 1.25]，只在风险预算内微调 |
| `constraints` | 硬约束 | 直接过滤战术库 |

## 2. 输出参数（决策卡 Decision Card）

系统对每个 `trade_request` 输出一张决策卡，**格式固定**：

```yaml
decision_card:
  card_id: DC-2026-014        # 流水号，与日志 card_id 一一对应，归档进 cards.md
  verdict: GO                 # GO | WAIT | NO_GO
  verdict_reason: 一句话

  # —— 核心判据检验（系统的心脏）——
  inequality_check:
    trade_type: directional   # directional | income
    p_estimate: 0.46          # 校准折减后的成功概率（§4）
    p_range: [0.38, 0.54]     # 诚实呈现不确定性
    rr: 2.8                   # 方向性：(加权止盈−入场)/(入场−止损)；收租型改报 EPR
    p_x_rr: 1.29              # 方向性须 >1；收租型报 EPR + 三档稳健性 + 尾部约束（§0.1）
    l0_z: 1.19                # L0 目标自洽 Z 值（§3 L0a）；>2 的请求不应走到出卡（应已被还价）
    expectancy: +0.75R        # = 0.46×2.8 − 0.54

  # —— 仓位 ——
  position:
    risk_amount: $750         # = min(NAV × max_loss × M_regime × M_valuation × M_conviction, 1.2% NAV)
    size: 81 股 @ ~181        # = risk_amount / (entry − stop) = 750 / 9.2；期权按每张最大亏损
    size_pct_nav: 14.7%       # 名义 81×181 ≈ $14.7k，示例按 NAV = $100k
    check: 81 × 9.2 ≈ $745    # 校验行：股数 × 止损距 = risk_amount
    caps_hit: []              # 触发了哪条上限（1/10 Kelly / 波动预算 / 保证金闸门）

  # —— 入场 ——
  entry:
    tactic: PB-2 趋势回调      # 来自战术库 §7
    zone: [178.5, 182.0]
    tranches: [50% @ 181, 50% @ 179]
    trigger: 具体触发条件（价格/量/事件）
    valid_until: 2026-08-08   # 过期作废，防追单

  # —— 止损（先于止盈设计）——
  stop:
    initial: 171.8            # 结构位下方 − 0.5×ATR(14)
    basis: 结构 + ATR 说明
    trailing: 触及 T1 移至成本；此后 3×ATR 吊灯止损
    time_stop: horizon 结束论点未验证 → 无条件退出

  # —— 止盈 ——
  targets:
    T1: 196 (+1.6R, 卖 1/3)
    T2: 214 (+3.5R, 卖 1/3)
    T3: runner（吊灯止损跟踪）

  # —— 风险与收益预估 ——
  risk_report:
    scenarios:                # 三情景概率和 = 1（bull/base/bear 各含触发条件）
      bull: {prob: 0.30, pnl: +$2,600}   # 三情景是含分批止盈的粗粒度 PnL 分布；
      base: {prob: 0.45, pnl: +$900}     # 其加权盈利概率允许高于 p_estimate——
      bear: {prob: 0.25, pnl: −$750}     # p 定义为「触及 T1 前不触止损」的概率
    ev_dollars: +$1,000
    portfolio_after: 总 open risk 2.9% / 同叙事敞口 24% / 压力测试通过（§5.5）

  # —— 论点封存（预注册，平仓后照此打分）——
  thesis_registration:
    claim: 论点原文一句话
    quantified_triggers: [可验证的触发条件]
    invalidation: [可证伪的失效条件——触发即无视价格退出]
    implied_p: 0.46           # 与 p_estimate 一致，写死不许事后改
    review_schedule: 每周五；事件日次日强制

  # —— 对抗辩论记录（§8：day 1轮 / swing 2轮 / position+ 3轮）——
  debate:
    rounds: [{bull: …, bear: …}, …]
    adjudication: 综合 N 轮辩论，p 修正 −3pp / RR 修正 +0.2，理由…
```

### 裁决规则

- **GO**：验收判据通过（§0.1）且所有组合约束（§5.3–5.5）满足。
- **WAIT**：判据不成立但可由入场价改善弥补（等回调把 RR 从 1.8 拉到 2.5）→ 给触发条件挂起，`valid_until` 到期作废。
- **NO_GO**：任何合理入场价下判据都不成立，或组合约束被击穿，或 L1 处于禁区。**NO_GO 必须给替代方案**（换工具/换标的/降仓/放弃）。

纪律：决策卡是 NO_GO 而仍想做 → 只能改输入参数重跑，**不能讨价还价改输出**。

## 3. 评估引擎（L0 前置闸 + 五层）

收到 `trade_request` 后先过 L0 前置闸，再按固定顺序过五层，禁止跳层：

```
L0 目标自洽 + 观点确认 →  Z 值还价闸；view 结构化并经用户确认
L1 宏观流动性 regime  →  M_regime 风险预算乘数（先定"能下多大注"）
L2 叙事与命题         →  Δp_narrative（这个故事处于什么阶段）
L3 基本面与估值       →  准入门槛 + M_valuation + Δp_fundamental
L4 技术与情绪         →  入场区/止损/止盈 → RR 的计算基础
L5 工具与结构         →  正股 or 期权结构 → 战术路由（§7）
```

### L0 前置闸（v1.1 新增）：目标自洽预检 + 观点结构化确认

**L0a 目标自洽预检**——先检验请求本身自洽，再消耗五层评估：

```
Z = expected_return / (σ60 × √(horizon_交易日 / 252))
```

horizon 取档位中位交易日数：day=1、swing=25、position=85、campaign=160（用户可显式覆盖）。σ60 缺失时用 `ATR14/现价 × √252` 近似并标注。instrument=option 且目标为权利金收益率口径时，先折算成底层所需波幅再算 Z（卡上标注折算口径）。

| Z 值 | 判定 | 动作 |
|------|------|------|
| ≤ 1.0 | 自洽 | 进入五层评估 |
| 1.0 – 2.0 | 偏紧 | 继续评估；决策卡标注「目标处于 1–2σ 区间，达成依赖强催化剂」 |
| > 2.0 | 不自洽 | **不进入评估，先还价** |

配套检查：`隐含 RR 上界 = expected_return × entry / (1.5 × ATR14)`（最紧合规止损 §6.2 下的 RR 上界）；< 1.5 → 方向性交易在该波动结构下无法同时满足目标与止损纪律 → 还价。

**还价是输出不是拒绝**：给出 2–3 组修改后的可行参数（降目标至 ≤1.5σ / 延长 horizon / 改 defined-risk 期权结构把最大亏损硬封顶、用凸性换目标 / 放弃）供用户选择重跑。用户坚持原参数 → 直接出 NO_GO 卡（理由：L0 不自洽），不进入五层。

**L0b 观点结构化确认**——把 view 解析为结构化观点，回显用户确认后才进 L1：

```yaml
view_parsed:
  direction_implied: long         # 与 direction 字段冲突 → 必须当场指出
  strength: 强 | 中 | 弱
  time_window: 财报后两周
  catalysts: [8/28 财报, 新品发布]
  invalidation_candidates: [数据中心收入环比转负, 跌破 165 结构位]
  assumptions: [市场把 capex 上修解读为利好]
```

`invalidation_candidates` 经用户确认后才写入 `thesis_registration.invalidation`——**失效条件必须由用户亲口认可，不能由 AI 单方面代拟**（它是「论点失效开关」的扳机，解析错一次，整个失效机制就失效一次）。确认成本是一条消息，远低于按错误理解跑完五层。

### L1 宏观流动性 regime ——《三十年编年史》+ 美元流动性双评分

数据源：`美元流动性/data/processed/latest.json`（境内/离岸双评分 0-100，每周一自动更新）+ `book/data/regime_scores.json`（季频 A/B/C 体制 + 双线松紧分）。

**重要边界（该框架 V3 回测的诚实结论）**：流动性评分同期判别有效（AUC 0.589/0.616）但**无预测力**（领先 4 周 AUC≈0.50，择时夏普低于买入持有）。所以它只能当「风险状态调节器」，**永远不作为入场信号**。

**境内评分 → M_regime 映射表**：

| 境内流动性评分 | 状态 | M_regime |
|---------------|------|----------|
| ≥ 65 | 松 | 1.25 |
| 50 – 65 | 正常 | 1.00 |
| 35 – 50 | 偏紧 | 0.75（并收紧止损） |
| < 35 | 紧（历史 8 次压力事件均落此区） | 0.50，只做防御结构 |

**硬报警覆盖层**（任一触发 → M_regime = 0，禁开新仓，只减不加）：

- SOFR − IORB 20 日均值 > +10bp（回购尖峰线，2025-10-28 曾 +41bp 触发停缩）
- 准备金/GDP 跌破 8%（LCLoR 观察带下沿击穿）
- HY OAS 先于股指走阔 +150bp 且与指数新高并存（末端预警）

**优先级裁决**（防止与深跌型 playbook 冲突）：硬报警 M_regime = 0 覆盖一切 playbook，禁开新仓无例外；评分 < 35 但无硬报警时，PB-3/PB-5（其设计场景就是深跌）允许按预设档位的 **50%** 执行——若是标的级恐慌而非市场级压力（评分 ≥ 35），按 100% 执行。M_regime「降一档」的阶梯固定为 `1.25 → 1.0 → 0.75 → 0.5 → 0（= 停开新多）`。

**体制与结构判读**（季频，影响战术而非仓位）：当前 C 体制（地板·准备金充裕·财政主导）下**量比价重要**——盯净流动性（WALCL−TGA−RRP）而非利率水平；「由松转紧」连续两季 → 系统性降仓一档。股债 60 日相关 > +0.5 → 停用"债券对冲股票"假设，改现金/波动率对冲。离岸评分 <35 → 削减 EM/大宗/加密敞口。

**虹吸状态 → 战术形态过滤**（`compute_siphon_scores.py` 五分类）：

| 市场状态 | 允许的战术形态 |
|---------|---------------|
| 存量虹吸 | 只做叙事主线多头；叙事外资产回避；禁均值回归 |
| 虹吸酝酿 / 结构轮动 | 正常，主线优先 |
| 增量普涨 | 放宽标的选择，可加 Beta |
| 风险出清 | 防御结构 / 现金 / 只做收租型小仓 |

**规律库 checklist**：入场前用 `book_query.py rule kw <主题>` 拉相关规律卡（45 条 R-01~R-45，带证据数/反例），命中的规律作为 §4 Δp_regime 的依据，反例栏直接生成该笔的证伪条件。最常用：R-01（转紧→顶滞后 2-11 个月）、R-13（窄基新高+集中度极值=脆弱）、R-17（Fed Put 观测）、R-24（合成流动性）、R-38（BTC=净流动性高 Beta 影子）。

### L2 叙事与命题 —— intelligence.dance 命题库

## 4. 成功概率 p 的估计规则

p 不允许拍脑袋，流程固定四步：

```
p = clamp( (base_rate + Σ调整项) × calibration_factor, 0.25, 0.75 )
```

**第 1 步：基准率。** 按 playbook 取历史基准（§7 每个 playbook 带实测值；无历史数据的一律从 45% 起步，不许更高）。

**收租型（PB-1/5）整体豁免本节流程**：p 直接取逐笔回测统计值（如 QQQ 车轮 96.6%），不做 ×0.90 折减、不叠加 Δp 调整项、不走 clamp——EPR 对 p 极端敏感（盈亏平衡 p ≈ 95%），任何折减都会机械性杀死所有收租交易，那是死锁不是保守。收租型的校准走另一条路：月度 playbook 记分牌（§9）——实际胜率跌破回测胜率 −2pp → EPR 用实际值重算，不达 1.5 即停用该 playbook。其入场约束由 §0.1 的稳健性检验（p −2pp 仍 EPR ≥1.5）+ 尾部约束 + §5.5 四闸门承担。

**第 2 步：结构化调整项**（各层贡献，均有上限）：

| 调整项 | 来源 | 范围 |
|--------|------|------|
| Δp_regime | L1（regime 顺逆风 + 命中规律卡） | ±5pp |
| Δp_narrative | L2（命题验证状态 + 模式匹配） | ±10pp |
| Δp_fundamental | L3（score_riskadj 映射） | ±8pp |
| Δp_technical | L4（结构质量、入场位优劣） | ±8pp |
| Δp_view | 用户 view 中可验证的独有信息 | ±5pp |

**第 3 步：校准折减。** 日志 < 20 笔固定 ×0.90；≥20 笔按校准表（§9）：历史上"预测 55%"的桶实际只赢 45% → 该桶折减 ×0.82。

**第 4 步：钳位 [0.25, 0.75]**（方向性交易）。不允许输出 >75%——常规方向性交易没有那么高的确定性；<25% 说明根本不该做。

**呈现要求**：决策卡给出 p 区间（±8pp 起步）+ 每个调整项的取值与理由，让用户能逐项反驳。用户 view 同时作为「主观判断入库」（§9）：长期统计用户主观判断的命中率，动态决定 Δp_view 的权重——这是 intelligence.dance Idea Vault 机制的移植。

## 5. 仓位规则

### 5.1 风险预算法（主公式）

```
risk_amount = min( NAV × max_loss_per_trade × M_regime × M_valuation × M_conviction,  1.2% × NAV )
shares      = risk_amount / (entry − stop)       # 期权：risk_amount / 每张最大亏损
```

- `max_loss_per_trade` 默认 0.75% NAV，区间 [0.5%, 1.0%]。
- `M_regime` 来自 L1（0 / 0.5 / 0.75 / 1.0 / 1.25）；`M_valuation` 来自 L3（0.30–1.00）；`M_conviction = 0.75 + 0.125 × (conviction − 1)`。
- 乘数只能缩小到 0；放大侧由外层 `min(…, 1.2% NAV)` 显式钳位——**任何乘数组合都不能让单笔风险超过 1.2% NAV**。
- 做空：分母取 `|entry − stop|`，并把预估借券费计入本笔成本（V1 默认不做正股裸空，见 §7 路由）。

### 5.2 1/10 Kelly 上限（第二道闸）

```
f* = p − (1 − p) / RR
仓位风险上限 = f* / 10 × NAV
```

取 §5.1 与 1/10 Kelly 的较小值。为什么是 1/10 而不是常见的 1/4：GO 的必要条件 `p×RR > 1` 加上 p 钳位下限 0.25，使 `¼f*` 恒大于 1.2% NAV 硬顶——¼Kelly 是一道永远不会触发的假闸门。1/10 Kelly 的下界约 0.6% NAV，在低 p 高 RR 的交易上会真实收紧仓位。

### 5.3 组合约束（第三道闸）

- 总未平仓风险 `Σ(每笔距止损亏损)` ≤ `max_drawdown / 2`（容忍 10% → 上限 5%）。**收租型每笔按其压力情景亏损（−35% 跳空 + IV×3 口径；经 §0.1 尾部约束后必然 ≤ 1.2 × 该笔风险预算）计入 Σ**——没有价格止损不等于对组合风险贡献为零。
- 单一叙事/主题总名义敞口 ≤ 30% NAV（相关性 > 0.7 视同一个叙事合并计算——AI 链内 NVDA/AVGO/TSM/VRT 算一个叙事）。
- 单标的名义敞口 ≤ 15% NAV。期权计入名义的口径：买方按 delta 调整名义；**卖方按 `max(delta 调整名义, 50% × 行权价名义)` 计入**——0.80×ATH 的价外 put delta 只有 ~0.2，纯 delta 口径会把 6% 名义只记 1.2%，尾部敞口被系统性低估。
- 财报周内暴露于事件的持仓 ≤ 2 个。

### 5.4 波动预算（对齐 vol_tolerance）

```
单笔名义上限 = NAV × vol_tolerance / (σ_asset × √N_eff)
```

σ_asset 用 60 日年化波动；`N_eff` = 按 §5.3 叙事合并后的独立仓位数（**含本笔**）——同叙事持仓不算独立仓位，不享受 √N 分散折扣。`sharpe_target` 不进公式，作月度验收线（§9）：滚动夏普低于目标 → `max_loss_per_trade` 下调一档。

### 5.5 保证金与期权卖方四道闸门（第四道闸，PutWheel 防爆仓护栏实测值）

卖权利金类（PB-1/5）额外全部通过，**按保证金利用率而非价格机械减仓**：

1. 单笔卖 put 名义：宽基 ≤ 6% NAV、个股 ≤ 4% NAV；同方向空 put 总名义：宽基 ≤ 30%、个股 ≤ 20%（定死单值，不给区间——区间会被永远取宽端）。
2. 预估峰值账户杠杆 ≤ 1.25×；任何一周保证金利用率 > 0.40 = 危险区，只减不加。
3. 分档开仓：−20/−30/−40% 各档只开一次（实测：不分档单笔大仓 6.5× 杠杆 9 周爆仓；分档 3.46× 扛过 NVDA −66%）。
4. 压力自测：「瞬间 −35% 跳空 + IV ×3 会不会触发维持保证金追缴」——过不了就砍到过得了。

## 6. 止损与止盈规则

### 6.1 止损先于止盈设计

强制顺序：**先找结构止损位 → 算出 1R 距离 → 再检验目标位给不给得出足够 RR**。反向（先定想赚多少倒推止损）被禁止——那样止损会被压进噪音区。

### 6.2 初始止损

- 位置 = 关键结构位（前低/颈线/缺口沿/均线簇）再让出 `0.5 × ATR(14)`。
- 校验：止损距离 ≥ 1.5 × ATR(14)（swing 口径），否则属噪音区止损，换入场位或放弃。
- 期权卖方的"止损" = 结构最大亏损（开仓即定义死）+ §5.5 闸门；买方 = 权利金 50% 或底层结构位，先到先执行。

### 6.3 移动止损与止盈

- T1 = +1.5R 附近第一个技术阻力，落袋 1/3，止损移至成本。
- T2 = +3R 附近或测量目标位，再落袋 1/3。
- 余下 runner 用 3×ATR 吊灯止损。加权 RR = `(1/3×R_T1 + 1/3×R_T2 + 1/3×R_T3est)`，R_T3est 保守取 T2 同值。
- 优质核心档标的（三步法 quality ≥72）允许"让赢家跑、不在新高清仓"；周期股（cyc ≥70）例外——1.5×/2.5× 快速落袋。
- 拥挤衰竭度（虹吸框架 `100 − runway`）高企 → 收紧止盈紧迫度。

### 6.4 三类退出，缺一不可

1. **价格止损**：§6.2/6.3——回答"错了亏多少"。
2. **时间止损**：horizon 结束论点未验证 → 退出（横盘是论点失败的一种形态）。LEAPS 专用：DTE < 120 未兑现即平。
3. **论点失效开关**：`thesis_registration.invalidation` 触发 → 无视价格立即退出。价格还没跌不代表你没错。

## 7. 战术策略库（Playbooks）

六个 playbook 全部来自用户已有的回测与研究，参数可溯源。tradingforge 78 策略库（view/horizon/inst/risk 四匹配键）作扩展底座——V2 时给每条补 `rr_ratio`/`base_win_rate` 字段后并入。

两条路由总则：① L1 硬报警（M_regime = 0）覆盖一切 playbook，禁开新仓无例外（PB-3/PB-5 与 L1 的详细优先级见 §3 L1）；② **做空路由**：V1 阶段空头观点一律走 defined-risk put 结构（归入 PB-4 口径，base_rate 45%，最大亏损 = 权利金或价差宽度 = 1R），不做正股裸空。

### PB-1 · PutWheel 现金担保卖 put 轮（收租型）

- **适用**：宽基与优质均值回归票（QQQ/AAPL/GOOGL 型）。**超高成长票禁用**（NVDA 车轮 14.2% vs 持有 54.4%）；2023 式纯牛市里整体跑输持有——用于震荡与回撤环境。
- **规则**：周五按 `Strike% × 历史最高价` 卖现金担保 put；周复盘，收益率 ≥ Trigger 即平仓按新 ATH 重开（仅盈利展期）；到期价外落袋；被行权则接货持有至 `Sell% × 前高` 限价卖出。
- **分资产预设**（8.4 年真实期权链回测选优）：

| 资产类型 | Strike% | DTE | Trigger | Sell% | 实测（年化/回撤/Sharpe） |
|---------|---------|-----|---------|-------|--------------------------|
| 宽基（QQQ） | 0.80 | 14–30d | 50–65% | 110–120% | 18.1% / −9.9% / 1.35 |
| 优质龙头（AAPL） | 0.75–0.80 | 14–30d | 65% | 120–135% | 29.5% / −16.6% / 1.68 |
| 高波动周期（MU） | 0.80–0.85 | 14d | 65–75% | 110–120% | 小仓；37.3% / −49.4% / 0.78 |

- **判据口径**：QQQ 逐笔胜率 96.6%、均值 +0.44%、亏损均值 −5.78%、最差 −13.0%、被行权率 5.6% → EPR ≈ 2.2 ✓（稳健性：p −2pp = 94.6% 时 EPR = 0.946×0.44 ÷ (0.054×5.78) ≈ 1.33，落 §0.1 **半仓档**——本 playbook 全部仓位预设与 §5.5 闸门按 50% 执行）。仓位过 §5.5 四闸门。
- **适用白名单（量化）**：σ60 ≤ 35% 且 score_riskadj ≥ 55；超出即禁用 PB-1（「优质均值回归」不是一个可以自由解释的形容词）。
- **参数纪律**：Strike% / DTE / Trigger / Sell% 偏离上表预设 → 回测统计（胜率/EPR/最差亏损）**全部作废**，按无历史 playbook 处理（WAIT，先小仓采集数据）。
- **入场时机**：贴 ATH 时 0.80×ATH 权利金极薄（年化 0-5%），肥租金要等回调——权利金年化 < 8% 时 WAIT。

### PB-2 · 趋势回调买入（方向性）

- **适用**：三步法核心档/性价比档标的（quality ≥72 或 score_riskadj ≥55），上行趋势中。
- **触发**：回调至 MA50/关键结构位且企稳信号出现；虹吸状态非"风险出清"。
- **默认参数**：RR ≥ 2.5；基准 p = 45%（无个人历史前）；止损按 §6.2；分批 §2 模板。
- **禁区**：价格/MA200 > 1.45 的抛物线段不做回调买入（那是 PB-6 的领域）。

### PB-3 · 恐慌加仓 LEAPS（方向性，防守定位）

- **适用**：核心档优质标的自前高回撤 ≥ 20%，在既有核心持仓（受 §5.3 上限约束）之外预留弹药。
- **规则**（组合口径，已从单资产回测重标定）：每档 LEAPS 权利金 ≤ 1.2% NAV、三档合计 ≤ 3.6% NAV；**权利金全额 = 该笔 1R**，计入 §5.3 总未平仓风险；−20/−30/−40% 三档各只开一次；**只买 ≥18 个月**（≤1 年期全网格最差，短端 IV-crush）；虚值程度不重要（别为彩票付溢价）。
- **管理**：DTE < 120 未兑现即平（时间止损）；优质票让赢家跑，周期股 1.5×/2.5× 快速落袋。
- **定位**：风险整形（QQQ 实测削回撤 5 点、ΔSharpe +0.10）而非增收益——决策卡标注"防守型"。

### PB-4 · 事件驱动（方向性，defined-risk 强制）

- **适用**：财报/宏观事件前后有明确催化剂论点。
- **规则**：只做定义最大亏损的结构（垂直价差等）；IV rank > 60 用 credit 结构、< 30 用 debit 结构；事件前建仓的最大亏损即 1R；命中 PAT-003 形态（高估值+拥挤+存疑催化剂）→ 只做小仓或放弃。
- **默认参数**：debit 结构 RR ≥ 2.2（用价差行权价设计凑 RR，不许靠抬 p 过线——基准 p=45% 下 RR 1.5 是数学上永远过不了判据的默认值）；credit 结构按 EPR ≥ 1.5 口径；事件后 48h 内无论方向了结或转常规持仓管理。
- **预期管理**：事件 debit 单的设计预期就是高拒绝率（基准通过率 < 20% 属正常）——连续 NO_GO 不代表系统坏了，代表大多数财报单本来就不该做。

### PB-5 · 卖 put 融资买 LEAPS（收租+凸性，进阶）

- **适用**：满仓账户深跌时的保证金战术。实测是放大 beta 不是 alpha（αSharpe 最高 +0.02）——预期收益按 beta 放大器口径评估，不当 alpha 讲。
- **规则**：深跌分档「卖 30d 价外 12-18% put + 权利金买 1.5-2 年 LEAPS」；每档名义 4-6% NAV、总空 put 名义 ≤ 20-30%、−20/−30/−40% 三档各一次。
- **硬护栏**：§5.5 全套；实测参考 sz4-6%/cap20-30% → 峰值杠杆 1.31×、0 爆仓（NVDA 穿越 2022 −66%）；sz30% 第 22 周强平归零。**注意**：三档满配可能在第三档触发 §5.5 的 1.25× 杠杆闸门——**以闸门为准提前停止加仓**，宁可少吃最后一档。

### PB-6 · 超买防守切换（管理型）

- **触发**：持仓标的 RSI > 70 或 价格/MA200 > 1.45（切换实验最稳信号，NVDA 纯车轮 9.9% → 切换后 36.4%）。
- **动作**：从裸持有切换到 covered call / collar / 部分落袋 + 卖 put 接回；**不是清仓信号**——切换从不同时打败纯持有与纯车轮，最优解仍是"按资产选模式"，此 playbook 只处理极端超买段。

- **Claude 桌面版 Project（备用/移动端）**：手贴数据，流程如下。

```
① Claude 桌面版建 Project「交易决策引擎」
   项目指令 = CLAUDE-DESKTOP-PROMPT.md 全文
   项目知识 = 本 SPEC + 四份快照（周度更新，见下）

   每张 GO/WAIT 卡由用户复制归档到项目知识 cards.md（追加式，只增不改）——
   它是跨对话的唯一台账：event_key 去重、失效条件核对、月检打分都以它为准
```

**分批成交的记账时点**：首笔成交即落日志行；`entry` 记已成交部分加权均价、`size_R` 记实际已成交风险金额（非计划值）；后续 tranche 成交回贴后更新同一行并注「rev：加仓至 X」；`valid_until` 过期未成交的剩余档位自动作废，不追单。

**WAIT 卡生命周期**：挂起的 WAIT 卡登记进 TRADE-JOURNAL 的 WAIT 登记表；**用户是唯一跟踪人**（可在 IBKR 挂价格提醒对应触发条件）；触发后**必须重跑评估**——允许快速通道：只复核 L1 regime 与 L4 入场结构，L2/L3 快照未更新则沿用原卡；`valid_until` 过期即作废，周检时清理。

**项目知识的四份快照**（已有自动化产出，周一手动拖入即可）：

1. `美元流动性/data/processed/latest.json` + `dashboard_curated.json`（周一 launchd 自动更新）
2. intelligence.dance B 板块最新周报的命题概率表（每周日发布）——**保留最近两周各一份**，周检的「悲观路径周 Δ」靠两份对比才算得出来
3. `AI 投资/周度跟踪/` 最新修正建议（周一 launchd 自动更新）
4. `PutWheel量化分析/engine/current_state.json`（车轮实时报价快照，按需跑 `current_state.py`）

外加一份 `cards.md`（决策卡归档台账，见流程③）。个股技术面数据（现价/结构位/ATR/RSI/IV rank/财报日）快照不覆盖——由用户在每笔 trade_request 的市场数据块里提供，**缺市场数据不出决策卡**。

**对抗辩论轮数**（intelligence.dance 辩论纪律移植）：day 1 轮、swing 2 轮、position/campaign 3 轮 bull⇄bear，裁决段必须显式给出对 p 和 RR 的修正量（±pp），禁止无触发证据的调整。

## 9. 交易日志与校准闭环

字段与月度校准报告模板见 [TRADE-JOURNAL.md](TRADE-JOURNAL.md)。核心机制：

- **论点预注册**（编年史 tripwires 协议移植）：每笔交易的 `thesis_registration` 开仓时封存——论点原文、量化触发/证伪条件、隐含 p、本卡已计入的 event_key 清单、核对日程；**只增不改**。决策卡经 `card_id` 与日志行一一对应，归档在 cards.md（§8③）。
- **Brier 分数**：`mean((p_pred − win)²)`，月度计算，长期必须 < 0.25（无信息基准）。
- **校准表**：按 p_pred 分桶对比实际胜率 → 生成 §4 calibration_factor；某桶 factor < 0.85 持续两月 → 对应 playbook 仓位减半。
- **Playbook 记分牌**：< 20 笔半仓观察；连续 20 笔期望值为负 → 停用检修。
- **主观判断打分**：用户每次 view 作为带 id 的 prior 入库，平仓后打分（命中/部分/反证）→ 长期得出"用户主观判断命中率"，动态定 Δp_view 权重。
- **持仓复核触发器**（scorer flag 规则移植）：相关命题条件分 3 连同向且 |Σdelta| ≥ 10，或悲观路径相对初值 |Δ| ≥ 0.20 → 强制复核。
- **统计常识**：edge ≈ +0.2R/笔、σ ≈ 1R → 需约 100 笔才能 t≈2 确认优势为真。前 100 笔的任务是活着并收集数据。

## 11. 风险清单与实用建议

1. **p 高估的自我欺骗是系统最大风险**。防线：钳位 [0.25,0.75] + 校准折减 + 逐项可反驳的打分卡 + Brier 追踪。前 100 笔别谈"证明系统有效"。
2. **高胜率错觉（收租型专属）**。QQQ 车轮一笔最差亏损（−13%）= 30 笔平均权利金；96.6% 胜率的钱是尾部一次性还回去的。EPR + 尾部约束 + §5.5 四闸门缺一不可。
3. **流动性评分不是择时信号**。V3 回测已钉死（领先 AUC≈0.50）：它只调节风险预算，谁拿它择时谁亏钱。
4. **概率双重计入**。同一事件在日评和周评里各调一次 p 是最隐蔽的系统性偏差——event_key 去重纪律必须执行。
5. **命题库数据缺陷**。B-006 条件表污染（引用只取 COND-011/012）；覆盖不全的命题标"无先验"而不是编一个。
6. **战术错配**。车轮用在 NVDA 类超高成长票 = 主动放弃 alpha；买 call 用在车轮擅长的均值回归票 = 反转 edge、回撤放大 1.5–4.5×。先分型再选战术（§7 路由）。
7. **保证金的死法是路径不是终点**。同样总杠杆，不分档 9 周爆仓、分档扛过 −66%。分价位分时点 + 按利用率机械减仓。
8. **Regime 突变与跳空**。止损单保护不了隔夜跳空——事件周只做 defined-risk；股债相关 > +0.5 时对冲假设失效。
9. **过拟合警示**（红队结论移植）：回测参数跨档 Sharpe 差多在噪声内，参数预设"当原则用别当圣经"；名单冻结向前验证，"股价上涨不构成升档依据"。
10. **系统外纪律**：`exit_reason = manual` 占比 > 20% → 当月禁止提高任何仓位参数。系统防不了不用系统的人。
