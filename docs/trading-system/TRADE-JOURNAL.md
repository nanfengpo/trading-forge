# 交易日志与校准模板

> 配套 [SPEC.md](SPEC.md) §9。日志是校准闭环的数据底座——**没有日志，p 的估计永远是自我感觉**。
> V1 阶段用一个 Markdown 表格（或 Google Sheet / CSV）维护即可，字段不许增删。
> skill 载体（v1.1 起）的台账文件固定在仓库 `docs/trading-system/journal/`：`trades.md`（本模板的实例，含 WAIT 登记表）与 `cards.md`（决策卡归档）；Desktop 载体维持项目知识里的 cards.md。

## 1. 日志表结构

| 字段 | 说明 | 示例 |
|------|------|------|
| `id` | 流水号 | T-2026-014 |
| `card_id` | 对应决策卡编号（卡归档在项目知识 cards.md，跨对话台账） | DC-2026-014 |
| `date` | 开仓日期 | 2026-07-28 |
| `symbol` | 标的 | NVDA |
| `playbook` | 战术编号（SPEC §7） | PB-2 趋势回调 |
| `direction` | long / short / neutral | long |
| `horizon` | day / swing / position / campaign | swing |
| `p_pred` | **开仓前**决策卡里的 p（折减后） | 0.46 |
| `rr_planned` | 开仓前的计划盈亏比 | 2.8 |
| `entry` | 实际成交均价 | 180.6 |
| `stop` | 初始止损 | 171.8 |
| `size_R` | 风险金额（$ 与 %NAV） | $750 / 0.75% |
| `exit_date` | 平仓日期（分批则记最后一笔） | 2026-08-21 |
| `exit_price` | 加权平仓价 | 203.4 |
| `r_realized` | 实际盈亏（R 倍数） | +2.6R |
| `outcome` | win / loss / scratch（±0.25R 内算 scratch） | win |
| `exit_reason` | target / stop / time / invalidation / manual | target |
| `thesis_one_line` | 开仓论点一句话 | DC capex 上修 + 回调至 50MA |
| `lesson` | 一句复盘（可空，但连续 3 笔亏损后必填） | T1 落袋过早 |

**纪律**：`p_pred`、`rr_planned` 必须在开仓前写死，事后不许改——这两列是校准的原材料，改了整个系统就瞎了。`manual`（无规则平仓）出现频率是纪律水平的直接读数，月度复盘必看。

补充口径：

- **论点预注册**：每行日志对应决策卡的 `thesis_registration`（论点原文 + 量化触发 + 可证伪失效条件 + 隐含 p + event_key 清单），协议同《编年史》tripwires——只增不改，平仓后按 hit/partial/miss 打分。
- **收租型交易**（PB-1/5）：`rr_planned` 列改记 EPR（期望盈亏比）；`p_pred` **记逐笔回测基准值（不折减、不叠加调整项**，SPEC §4 豁免条款）；`r_realized` 仍以本笔风险预算为 1R 折算，保证跨类型可汇总。
- **分批成交**：首笔成交即落行；`entry` 记已成交部分加权均价、`size_R` 记实际已成交风险金额；后续 tranche 成交后更新同一行并在 `lesson` 注「rev：加仓至 X」；`valid_until` 过期的剩余档位作废不追单。

### 期权记账约定

- `symbol` 记底层 + 结构简码，如 `NVDA 170/160P 0815 credit`。
- `entry` / `exit_price` 记**组合净价**（credit 为正）；多腿组合一笔一行，以组合净损益对本笔风险预算折算 `r_realized`。
- 车轮（PB-1）：每次卖 put 独立一行（与回测口径一致）；被行权接货另起一行、`playbook` 标 `PB-1A`，两行在 `lesson` 列互记关联 id；盈利展期 = 平旧开新记两行。
- PB-5 的卖 put 腿与 LEAPS 腿到期不同：记两行，各自对本笔风险预算折算，`lesson` 互记关联。

## 2. 月度校准报告（每月末让 AI 依据日志生成）

### 2.1 Brier 分数

```
Brier = mean( (p_pred − win)² )        # win: 赢=1，输=0，scratch 剔除
```

- 全填 0.5 的无信息基准 = 0.25。系统长期必须低于它，否则 p 的打分卡（SPEC §4）没有增量信息。
- 趋势比绝对值重要：连续 3 个月上行 → 检查是哪个调整项在系统性说谎。

### 2.2 校准表（生成 SPEC §4 的 calibration_factor）

| p_pred 分桶 | 笔数 | 实际胜率 | calibration_factor |
|------------|------|---------|--------------------|
| 0.25–0.40 | — | — | 实际胜率 ÷ 桶中值 |
| 0.40–0.50 | — | — | … |
| 0.50–0.60 | — | — | … |
| 0.60–0.75 | — | — | … |

- 样本 < 20 笔的桶沿用全局默认 ×0.90。
- 某桶 factor < 0.85 持续两个月 → 该桶对应的常用 playbook 仓位减半，直到校准修复。

### 2.3 Playbook 记分牌

| playbook | 笔数 | 胜率 | 平均盈利(R) | 平均亏损(R) | 期望值(R/笔) | 状态 |
|----------|------|------|------------|------------|--------------|------|
| PB-1 … | — | — | — | — | — | 正常 / 半仓观察 / 停用检修 |

状态规则（SPEC §9）：< 20 笔 → 半仓观察；连续 20 笔期望值为负 → 停用检修（找出规则漏洞并修订 SPEC 后才能复用）。

### 2.4 组合层验收

数据来源：**IBKR PortfolioAnalyst 导出的近 3 个月月度收益率 / 夏普 / 最大回撤**（月检时随日志一并贴入）。未提供则该两项标「缺 NAV 数据未验收」跳过——禁止用逐笔 R 序列代算夏普（口径与年化都不可比，却会驱动降档硬动作）。

- 滚动 3 个月夏普 vs `sharpe_target`：低于目标 → `max_loss_per_trade` 下调一档（0.75% → 0.5%），连续两季达标才能调回。
- 最大回撤 vs `max_drawdown`：触及容忍值的 70% → 全组合 M_regime 强制降一档，新开仓暂停一周。
- `exit_reason = manual` 占比 > 20% → 当月不许提高任何仓位参数。

## 3. 周五组合体检（每周贴给 AI 的固定问题）

1. 当前总 open risk（Σ 距止损亏损）是多少，距 `max_drawdown / 2` 上限还有多少？
2. 各叙事敞口占比（相关性 > 0.7 合并），有无超 30%？
3. 哪些持仓已触及 T1 应移止损至成本？哪些吊灯止损需要上移？
4. 未来两周事件日历（财报/宏观数据）与暴露持仓对照。
5. 有无 WAIT 状态的挂起决策卡已过 `valid_until` 应作废？
